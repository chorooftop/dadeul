# 날씨 투표 위젯 (MVP)

> 제품 정책 인터뷰 확정: 2026-08-19 (시군구 / 슬라이딩 윈도우 2h / 재투표=갱신 / 1투표=1크레딧 / 운영자 큐레이션 / 익명 기기 계정)
> 코드 레포 미생성 — 이 spec이 현재 유일한 진실

## Problem & Motivation

기상청 예보는 "예측"이고, 유저가 알고 싶은 건 "지금 그곳에 실제로 비가 오는가"다. 그 답을 가장 잘 아는 건 지금 그곳에 있는 사람들이다. [날씨 투표][term-weather-option]로 사람들이 센서가 되고, 그 집계를 [홈화면 위젯][action-tally-feed]으로 상시 노출하면 "앱을 열지 않아도 보이는 집단지성"이 된다. 투표 참여가 [크레딧][entity-credit-wallet]이 되어 다른 주제 참여로 이어지는 루프가 리텐션 엔진이다.

## Scope

- **온보딩**: 최초 실행 시 [익명 기기 계정][entity-device-account] 자동 생성 → 위치 권한 요청 → [지역 판별][action-region-resolve] (거부 시 수동 지역 선택)
- **홈 화면**: 내 지역 날씨 집계 + 투표 버튼(선택지 4개) + 크레딧 잔액 + 활성 큐레이션 주제 목록
- **투표**: [날씨 투표·재투표][action-vote-cast], 크레딧 적립 피드백, 큐레이션 주제 투표(크레딧 차감)
- **위젯**: iOS WidgetKit + Android Glance — 내 지역 1위 선택지·비율·집계 시각 표기, 탭하면 앱 투표 화면
- **집계**: [슬라이딩 윈도우 2시간][rule-sliding-window-tally], [최소 표본 미달 처리][rule-min-sample-display]

## User Flow

1. **첫 실행**: 계정 자동 생성 → 위치 권한 안내("시군구 단위만 사용, 좌표 저장 안 함") → [지역][entity-region] 확정 → 홈 진입
2. **첫 투표**: 홈에서 날씨 선택지 탭 → 즉시 반영된 집계 + "+1 크레딧" 피드백 → 위젯 추가 유도 시트
3. **위젯 루프**: 홈화면에서 "☔ 강남구, 비 온다 73% · 12분 전" 상시 확인 → 날씨 급변 시 탭 → 앱에서 [재투표(갱신)][rule-revote-replace]
4. **크레딧 소비**: 홈의 큐레이션 [주제][entity-topic] 카드 → 크레딧 1 차감 투표 → 전국(또는 지역) 집계 확인
5. **재방문**: 위젯이 자연 진입점 — 푸시 없이도 하루 수회 노출

## Core Requirements

1. **서버가 단일 진실원.** 집계·윈도우 판정·크레딧 잔액을 클라이언트가 재계산하지 않는다. [투표 응답][action-vote-cast]과 [집계 피드][action-tally-feed]의 값만 표시한다.
2. **유저당 주제별 유효 표는 항상 1개.** 재투표는 갱신이며 크레딧 이벤트를 만들지 않는다 ([재투표-갱신][rule-revote-replace], [크레딧-지급][rule-credit-grant]).
3. **위젯은 낡음을 정직하게 표기한다.** `computedAt` 기준 "n분 전"을 항상 표기 — 위젯 갱신 제약(iOS 타임라인 예산)상 최신성을 보장할 수 없으므로 낡음을 숨기지 않는 게 신뢰 전략이다.
4. **위젯 갱신 전략** (2026-08-19 확정): **30분 주기 타임라인 + 내 지역 1위 선택지 변경 시에만 silent push**로 즉시 갱신(`reloadTimelines`). 비율 변화만으로는 push하지 않는다 — iOS 타임라인 예산 보호. 지역별 1위 변경 감지는 집계 스냅샷 갱신 시 서버가 판정한다.
5. **좌표는 저장하지 않는다.** [지역판별][action-region-resolve] 즉시 폐기, 시군구 코드가 저장 최소 단위.
6. **표본 미달 지역은 참여 유도로 전환.** "1명이 100%" 같은 우스운 화면을 만들지 않는다 ([최소표본-표시][rule-min-sample-display]).
7. **오프라인/실패 시 투표는 유실 명시.** 낙관적 반영 후 조용한 실패 금지 — 실패하면 되돌리고 알린다.
8. **전국 오픈 + 밀도 UX** (2026-08-19 확정): 지역 차단 없이 전국 허용. 표본이 얇은 지역은 [최소표본-표시][rule-min-sample-display]의 참여 유도 화면이 기본 경험이 되도록 설계 — 빈 지역이 고장이 아니라 "첫 투표 기회"로 보여야 한다.

## Scenarios

**골든패스**: 첫 실행 → 권한 허용 → 강남구 판별 → "비" 투표 → +1 크레딧 → 위젯 추가 → 2시간 뒤 위젯에 갱신된 집계 → 비 그침 → 위젯 탭 → "맑음"으로 재투표(크레딧 없음, 표 교체) → 큐레이션 주제에 크레딧 1 소비

**에러 경로**:
- 위치 권한 거부 → 수동 지역 선택 화면 → 이후 언제든 설정에서 GPS 전환
- 해외 좌표(`REGION_UNRESOLVED`) → 수동 선택 fallback
- 크레딧 0에서 큐레이션 투표(`INSUFFICIENT_CREDIT`) → "날씨 투표하고 크레딧 받기" 유도
- 마감 주제 투표(`TOPIC_CLOSED`) → 결과 화면으로 전환

**엣지**:
- 윈도우 내 표 전부 소멸(2시간 무투표 지역) → 표본 미달 표기로 자연 전환
- 이동 중 지역 변경(강남→분당) → 다음 지역판별 시 캐시 갱신, 기존 표는 투표 시점 지역으로 유지
- 기기 시계 조작 → 서버 시각만 사용하므로 영향 없음
- 앱 재설치 → 플랫폼 복원(iOS Keychain / Android Auto Backup)으로 같은 계정·크레딧 유지, 복원 실패 시에만 새 계정 ([기기계정][entity-device-account])
- 눈(❄️)이 4월에 숨겨져도 3월 말의 눈 표는 윈도우 소멸 전까지 집계에 유지 ([날씨선택지][term-weather-option])

## Out of Scope

- 유저 생성 주제, 댓글·채팅 등 커뮤니티 기능
- 소셜 로그인·프로필 (익명 기기 계정만)
- 읍면동 세분화, 인접 지역 fallback 집계
- 푸시 알림 마케팅 (위젯 갱신용 silent push만)
- 기상청 API 연동·예보 비교 (투표 데이터만으로 시작)
- 크레딧 구매·환전 등 수익화
