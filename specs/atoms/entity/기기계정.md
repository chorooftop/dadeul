# 기기계정

## Rationale

투표 앱에서 가입 요구는 치명적 이탈 지점이다. 익명 기기 계정은 진입장벽을 없애면서도 (계정, 주제) 유니크 제약으로 1인 1표를 지키는 최소 장치다. 단, 계정 키가 쉽게 리셋되면 재설치 반복 투표 어뷰징이 열리므로 키 보존 전략이 계정 설계의 핵심이다.

## Fields

- `id`: 서버 발급 계정 ID (기기 최초 실행 시 자동 생성)
- 접근 토큰: **SHA-256 해시만 저장** (DB 유출 ≠ 전 계정 탈취), bootstrap마다 **회전** — 이전 토큰 즉시 무효화 (2026-08-19 리뷰 반영)
- 계정 키 보존 (2026-08-19 결정 — **플랫폼 복원**):
  - iOS: **Keychain** 저장 (앱 삭제 후에도 보존) → 재설치 시 같은 계정 복원
  - Android: 계정 키를 **Auto Backup(`android:allowBackup`) 대상에 포함** → 재설치·기기 이전 시 복원
  - 복원 실패(Keychain 초기화, 백업 미동작) 시에만 새 계정 생성 — 크레딧은 이때 소멸하며, 별도 복구 수단은 제공하지 않는다 (익명 무마찰 원칙)
- 지역: 마지막 판별된 `term-region-code` 캐시 (위젯 표시용)

## Relationships

- 1 계정 : 1 크레딧지갑 (`entity-credit-wallet`)
- 1 계정 : N 투표 (`entity-vote`)

## Cross Map

- 위젯(WidgetKit/Glance)은 앱과 계정 토큰을 공유해야 한다 — iOS는 Keychain Access Group, Android는 앱 내 공유 저장소. 코드 착수 시 구현 앵커 기록
- **오픈 퀘스천**: 멀티 기기 유저의 어뷰징 여지(기기 수만큼 표), 추후 소셜 로그인 연동 시 계정 병합 절차
