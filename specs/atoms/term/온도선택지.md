# 온도선택지

## Rationale

하늘 상태·현상과 달리 온도 체감은 어떤 날씨와도 공존한다("맑고 더움", "비 오고 추움"). 이를 날씨 축에 섞으면 비율 의미가 깨지므로 **독립된 축**으로 분리해 축별 1인 1표를 유지한다. 사용자 경험은 한 카드에서 최대 2개 선택(날씨 1 + 온도 1)이지만 집계는 축별로 독립이다. 4종은 상호배타적 단일 스펙트럼이라 우세 규칙이 필요 없다. (2026-08-20 제품 결정 — 순수 복수 선택안은 counts 합 > totalVotes로 비율 의미가 붕괴해 기각)

## Definition

전체 4종, **상시 노출** (월 가변 없음 — 겨울의 "더움"도 유효한 체감):

| 값 | 라벨 | 노출 |
|---|---|---|
| `hot` | 더움 | 상시 |
| `warm` | 따뜻함 | 상시 |
| `cool` | 시원함 | 상시 |
| `cold` | 추움 | 상시 |

- 축 이름은 `temperature` — 날씨 주제(`kind=weather`) 전용이며 큐레이션 주제에는 존재하지 않는다
- 투표 제출은 기존 API 그대로 단건(PUT) — 서버가 optionValue로 축을 추론한다 (날씨 주제에서 이 4종 값이면 temperature 축)
- 축별 유효 표는 각 1개: (계정, 주제, 축) 유니크 — `entity-vote` 참조
- 집계·최소 표본(5표)·신선 신호 크레딧은 축별 독립 판정

## Usage Context

- 투표 제출(`action-vote-cast`)의 온도 축 선택 값 검증
- feed 응답 `weather.temperature.visibleOptions`의 어휘 (`action-tally-feed`)
- 위젯의 온도 병기 표시("맑음 60% · 더움 70%") — 구체 레이아웃은 spec-weather-vote-widget
