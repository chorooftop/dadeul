# 재투표-갱신

## Rationale

비가 그치면 유저는 표를 바꾸고 싶다. 재투표를 막으면 낡은 표가 '지금'을 오염시키고, 새 표를 추가로 받으면 한 명이 복수 표를 가진다. "갱신"만이 실시간성과 1인 1표를 동시에 지키는 모델이다. (2026-08-19 제품 결정)

## Applicability

- 모든 주제의 투표 제출 (`action-vote-cast`) — 날씨·큐레이션 공통
- 스키마 수준: [투표][entity-vote]의 (accountId, topicId) 복합 유니크가 이 규칙의 물리적 강제 장치

## Specification

- 같은 계정이 같은 주제에 다시 투표하면: `optionValue`·`castAt`을 갱신 (UPSERT), 새 레코드 생성 금지
- `firstCastAt`은 최초 값을 보존한다 — 크레딧 지급 판정(`rule-credit-grant`)의 기준점
- 재투표는 **크레딧을 다시 지급하지 않고, 다시 차감하지도 않는다** — 크레딧 이벤트는 최초 투표 1회에만 발생
- 같은 선택지로의 재투표도 `castAt`은 갱신된다 ("아직도 비 와" 재확인은 유효한 신선도 신호)

## DO NOT

- 재투표를 이력 테이블에 새 표로 쌓아 집계하지 않는다 — 집계 대상은 항상 현재 유효 표 1개
- 재투표 시 크레딧 원장에 이벤트를 만들지 않는다 (지급도 차감도)
- 재투표 횟수 제한을 두지 않는다 (MVP) — 어뷰징 신호가 실측되면 rule을 신설한다
