## Execution Order

1. [주제][entity-topic] 상태 검증 (active인가, 큐레이션이면 기간 내인가)
2. regional 주제면 지역 판별 결과 확인 (`action-region-resolve` 선행 또는 요청에 포함)
3. **축 추론** (2026-08-20): 날씨 주제에서 optionValue가 온도 4종이면 `temperature`, 아니면 `primary` 축 — 이후 검증·조회·집계 전부 그 축 안에서 수행
4. 기존 [투표][entity-vote] 조회(같은 축) → 신규/갱신 분기 ([재투표-갱신][rule-revote-replace])
5. 날씨 투표가 축별 신선 신호면 크레딧 +1, 큐레이션 신규 투표면 `creditCost` 차감 ([크레딧-지급][rule-credit-grant]) — 투표와 원자적.
   2026-08-22부터 소비 보류로 모든 주제 `creditCost=0` 운영 — 차감 단계는 메커니즘으로만 존재하고 실행 시 no-op
6. 집계 반영 및 갱신된 잔액·해당 축의 현재 집계를 응답

## Input / Output

- 입력: 주제 ID, 선택지 값, (regional이면) 좌표 또는 판별된 지역코드
- 출력: 유효 표 상태(선택지·castAt), 크레딧 잔액, 현재 집계 스냅샷 — 클라이언트가 추가 조회 없이 화면을 갱신할 수 있어야 한다
