# 지역판별

**구현 앵커:**

| 레이어 | 경로 |
|------|------|
| route | `apps/api/src/routes/regions.ts` — `POST /v1/regions/resolve`, `GET /v1/regions` |
| service | `apps/api/src/services/regions.ts` — 카카오 coord2regioncode(법정동 B 코드 상위 5자리), 지역 lazy upsert |
| test | `apps/api/test/api.test.ts` — 판별·캐시·REGION_UNRESOLVED |

## Rationale

기기별 로컬 지오코딩 데이터와 갱신 시점이 다르면 같은 좌표가 서로 다른 지역으로 판별되어
지역 집계의 신뢰가 깨진다. 서버가 하나의 제공자와 판별 규칙을 적용하고 시군구 코드만 계정에
캐시해야 모든 클라이언트가 같은 지역 집계를 사용하면서 위치정보 보유 범위도 최소화할 수 있다.

### 카카오 연동 정책 (2026-08-22 기준)

- 카카오맵 API 무료 쿼터는 개발자 계정에서 첫 번째로 활성화한 앱에 제공된다. 실제 적용 한도와
  사용량은 고정 수치를 명세하지 않고 앱 관리의 **[쿼터]** 에서 확인한다
- 쿼터를 초과하면 카카오가 429를 반환한다. 이는 다들 API 자체 호출 제한의
  `RATE_LIMITED` 429와 다른 upstream 장애로 취급한다
- `KAKAO_REST_API_KEY`는 서버 전용이다. iOS/Android 앱 번들에 포함하거나 클라이언트에 전달하지 않는다
- 카카오에 전달한 좌표는 지역 판별 요청에만 사용하며 서버 로그나 DB에 저장하지 않는다
- 배포 서버의 고정 IP가 확정되면 카카오 앱 관리에서 호출 허용 IP를 설정한다. 배포 전에는
  특정 IP를 임의로 확정하지 않는다

## Auth & Permissions

- 익명 기기 계정 토큰. 위치 권한 거부 유저의 대체 플로우(수동 지역 선택)는 spec에서 다룬다

## Execution Order

1. 클라이언트가 좌표(위도·경도)를 전송 — 좌표는 판별 즉시 폐기, 저장 금지
2. 서버가 카카오 coord2regioncode의 법정동(`B`) 응답을 [지역코드][term-region-code]로 변환한다
3. 변환된 코드를 [지역][entity-region] 마스터에 lazy upsert하고 활성 여부를 확인한다
4. 계정의 캐시 지역 갱신 후 지역 정보 응답

## Input / Output

- 입력: 위도·경도
- 출력: 지역코드, 표시명, 서비스 활성 여부

## DO NOT

- 좌표 원본을 로그·DB에 저장하지 않는다 — 프라이버시 원칙: 시군구 코드만이 저장 최소 단위
- 클라이언트 로컬 지오코딩 결과를 신뢰하지 않는다
- `KAKAO_REST_API_KEY`를 클라이언트 앱, 응답, 로그에 노출하지 않는다
- 카카오 쿼터 초과를 다들 API 자체의 `RATE_LIMITED`로 변환하지 않는다 — 운영 원인과 복구 주체가 다르다

## Error Handling

클라이언트의 복구 동선은 기존 토큰을 유지한다. 카카오 연동의 운영 원인은 HTTP 상태와 서버 로그로
구분하고 새 에러 토큰을 만들지 않는다.

| 조건 | HTTP 상태 / 토큰 | 처리 |
|---|---|---|
| 인증 토큰 없음·무효 | 401 / `UNAUTHORIZED` | 계정 부트스트랩으로 토큰 복원 |
| 판별 불가 좌표(해외 등) | 422 / `REGION_UNRESOLVED` | 수동 지역 선택 fallback 유도. 카카오는 이 경우 **400 + 본문 `code: -2`**("not in the service area")를 반환하므로 upstream 장애로 취급하지 않고 판별 불가로 변환한다 (2026-08-22 실측) |
| 비활성 지역 | 422 / `REGION_INACTIVE` | 활성 지역 선택 유도 |
| `KAKAO_REST_API_KEY` 미설정 | 503 / `INTERNAL_ERROR` | 서버 환경변수 설정 후 재시도 |
| 카카오 쿼터 초과(429) | 503 / `INTERNAL_ERROR` | 앱 관리 [쿼터] 확인, 서버 로그에 upstream 상태 기록 |
| 카카오 키 거부(401/403) | 502 / `INTERNAL_ERROR` | REST API 키·API 활성화 상태 점검, 서버 로그에 credential 오류 기록 |
| 그 밖의 카카오 비정상 응답(`code: -2`가 아닌 400 포함) | 502 / `INTERNAL_ERROR` | upstream 상태를 서버 로그에 기록하고 일반 서버 오류 동선 유지 |
| 카카오 네트워크·응답 파싱 실패 | 502 / `INTERNAL_ERROR` | 서버 로그에 원인을 기록하고 일반 서버 오류 동선 유지 |
