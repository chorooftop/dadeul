# 크레딧지갑

## Rationale

크레딧은 날씨 데이터 공급(투표)의 보상이다. 원안은 "큐레이션 주제의 입장권"까지 겸했으나,
**2026-08-22 결정으로 소비(입장권)는 보류** — 검증 안 된 핵심 루프에 마찰을 깔지 않기 위해 적립 전용으로 운영하고,
소비처는 후속 결정한다. 잔액만 저장하면 지급·차감 분쟁과 어뷰징 분석이 불가능하므로 원장(ledger) 구조는 그대로 필수다.

## Fields

- `accountId`: [기기계정][entity-device-account] (1:1)
- `balance`: 현재 잔액 (음수 불가)
- 원장 엔트리: `amount`(+적립/-차감), `reason`(`weather_vote` | `topic_vote_cost` | `ops_adjustment`), `refTopicId`, `createdAt`
  - 교정 기록 (2026-08-19 코드 실측): 원안의 `refVoteId`는 구현 불가 — 투표는 (accountId, topicId) 복합 PK라 대리키가 없다. `refTopicId`로 교정
- DB 제약: `credit_balance >= 0` CHECK — `ops_adjustment` 등 앱 검사를 안 거치는 경로에서도 음수 잔액 불가 (2026-08-19 리뷰 반영)
- 크레딧 정책 (2026-08-19 결정): **만료 없음(무기한)** + **일일 적립 상한 3크레딧** (상한 판정·리셋은 `rule-credit-grant`가 소유)

## Relationships

- 적립은 `rule-credit-grant`, 차감은 큐레이션 주제 투표(`entity-topic`의 `creditCost`)에서만 발생
  — 단 2026-08-22부터 소비 보류로 모든 주제 `creditCost=0` 운영, 차감 경로는 구현·테스트만 보존되고 실제로는 미발생
- 계정 복원([기기계정][entity-device-account]의 플랫폼 복원) 시 지갑도 함께 복원 — 복원 실패로 새 계정이 되면 잔액 소멸
