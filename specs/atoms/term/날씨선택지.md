# 날씨선택지

## Rationale

선택지가 많으면 표가 분산돼 슬라이딩 윈도우 표본이 얇아지고, 적으면 표현력이 부족하다. 전체 풀은 6개로 확정하되 계절에 안 맞는 선택지(여름의 눈)는 월 기준으로 자동 숨겨 분산을 줄인다. 노출 규칙을 서버 운영자가 수동 관리하지 않고 월 매핑 고정 규칙으로 두는 것이 결정 사항 — 운영 부담 없이 클라이언트·서버가 같은 규칙을 공유한다. (2026-08-19 제품 결정)

## Definition

전체 풀 6종 (wire 값은 영어 소문자 단일 토큰):

| 값 | 라벨 | 이모지 | 노출 월 |
|---|---|---|---|
| `sunny` | 맑음 | ☀️ | 상시 |
| `cloudy` | 흐림 | ☁️ | 상시 |
| `rain` | 비 | ☔ | 상시 |
| `wind` | 바람 | 🌬️ | 상시 |
| `fog` | 안개 | 🌫️ | 상시 |
| `snow` | 눈 | ❄️ | 11월~3월 |

- 노출 판정은 **서버 시각의 KST 월** 기준. 운영자 개입·서버 큐레이션 없음
- 월 매핑 표는 이 문서가 진실 공급원 — 변경은 이 atom 수정으로만 한다 (눈 11~3월 포함 2026-08-19 확정)
- 숨김 월에도 **기존 표는 유효** — 집계·표시에서 제외하지 않는다 (3월 31일 눈 투표가 4월 1일 소멸하면 안 됨, 슬라이딩 윈도우 자연 소멸에 맡긴다)
- 숨김 월의 선택지로 투표 제출 시 `INVALID_OPTION` (신규 제출만 차단)

## Usage Context

- 투표 제출(`action-vote-cast`)의 선택 값 검증 (해당 월 노출 집합 기준)
- 위젯 집계 표시("☔ 비 온다 73%")의 어휘
- 집계(`entity-tally`)의 counts 키 — counts는 항상 6종 전체 키를 갖고, 클라이언트가 노출 월 규칙으로 필터한다
